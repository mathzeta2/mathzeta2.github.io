    入门教程

    纸笔证明中，我们常写“由假设可知”“代入即得”。到了形式化证明里，需要把这些步骤表达成计算机能够检查的对象。Lean 可以帮助我们明确：用了哪些假设，当前还缺什么，以及结论是否确实由这些条件推出。

    这篇文章面向已经接触高等数学、线性代数或数学分析，希望开始学习形式化的读者。先整理值得跟读的教程，再用几个小例子体验证明过程。

    整理：zeta2 · 资料核对日期：2026 年 11 月 13 日。 本文使用 Lean 4；教程介绍是中文导读，链接指向原作者或官方维护的资源，代码示例为本文编写。

    入门教程系列：系列归档 · LaTeX：数学排版 · Manim：数学动画 · Lean：形式化证明

    一、先从哪份教程开始

    如果只选一本主教材，数学背景的读者可以先读 Mathematics in Lean。如果希望先知道“在 Lean 里证明一道题是什么感觉”，就先玩 Natural Number Game，再进入教材。这也是 Lean 官方学习页面提供的主要入门方向：官方学习资源。

    资源 适合什么时候使用 建议做法
    Natural Number Game 第一次接触证明助手 跟着关卡理解目标、改写和归纳；注意游戏有专门的教学环境
    Mathematics in Lean 想把熟悉的数学写成 Lean 作为主线，一边阅读一边完成对应的 Lean 文件练习
    Theorem Proving in Lean 4 想理解语法与逻辑基础 重点查阅命题、量词、等式和 tactics 章节
    A Glimpse of Lean 想较快接触数学证明实例 从 Introduction 开始，再选短路线或 Basics 目录
    mathlib API 文档 已经在写证明，想找定义和定理 当作工具书使用，不必从头读

    Mathematics in Lean（MIL） 使用 mathlib 数学库，面向数学形式化；Theorem Proving in Lean 4（TPIL） 更系统地介绍 Lean 的逻辑框架和核心语法。两本书可以互相补充，不需要先完整读完 TPIL 才开始做数学。教材的定位和使用方式见 MIL 第一章。

    Glimpse of Lean 的项目提供在线练习入口；基础部分之后还可以选择实数数列极限、环论等专题，适合作为从语法走向数学实例的过渡。具体路线见 项目说明。

    二、准备一个能看到证明状态的环境

    先在线体验

    打开 Lean Playground。本文最后一个例子使用实数与 ring，需要选择包含 mathlib 的环境，并将 import Mathlib 放在文件第一行。

    编辑器右侧的 InfoView 很重要：光标放到证明中的某一步时，可以看到当前假设和待证目标。初学时应养成“写一步、看一次目标”的习惯。在线入口和本地安装路径见 官方 Getting Started。

    再安装本地环境

    1. 安装 VS Code，以及发布者为 leanprover 的 Lean 4 扩展。
    2. 按扩展的 Setup Guide 完成 Lean 安装。
    3. 跟读 MIL 时，按 教材安装说明 下载教材项目，并用 VS Code 打开项目文件夹。
    4. 复制教材的 MIL 目录，在副本中做练习，保留原始练习供对照。

    学习数学时，直接进入教材项目更方便：项目已经声明所需依赖。一个只包含核心 Lean 的普通项目，并不会因为写了 import Mathlib 就自动安装 mathlib。

    已有项目中的 lean-toolchain 用来指定 Lean 工具链，依赖由项目配置与 lake-manifest.json 配合管理。跟教程时优先使用项目提供的版本；不要只升级 Lean 编译器，再期待旧依赖自动兼容。Lake 的项目与工具链说明见 官方 Lake 文档。

    三、先读懂目标，再选择策略

    例如当前状态是：

    可以读成：“P、Q 是命题，手里有 P 的证明 h，现在需要证明 Q。”符号 ⊢ 后面是当前目标；上面是当前可用的对象和假设。仅凭这个状态，通常无法证明 Q，还需要例如 P → Q 这样的条件。

    初学阶段可以先建立下面的对应关系：

    Lean 写法或策略 在证明中做什么
    P : Prop 声明 P 是一个命题
    h : P h 是 P 的一个证明
    intro h 对蕴含目标引入假设，或对全称目标引入对象
    exact h 用类型与当前目标匹配的证明完成目标
    apply h 用结论符合目标的定理，将所需前提变成新目标
    constructor 按构造方式拆解目标；例如把合取拆成两部分
    rw [h] 使用等式或等价关系改写
    rfl 处理两边按定义计算后相同的等式
    simp 使用化简规则简化表达式，有时可以直接完成目标

    这些策略的详细行为可查 TPIL：Tactics。不要把策略名当成万能口令：先看目标的形状，再判断它会把目标变成什么。

    四、五个小证明

    以下五个示例已于整理当日在官方 Playground 的 Stable Release：Lean v4.35.0（含 mathlib） 环境中通过检查，未产生错误或警告；#print axioms 的结果中没有 sorryAx。这里记录的是实际检查环境，不表示所有教材必须使用同一个版本。

    示例可以合并到同一个文件中。完整文件在文末提供，首行包含 import Mathlib；前四例只涉及基础逻辑与自然数，第五例使用 mathlib。

    1. 把两次推理连接起来

    已知 P→QP\to QP→Q 与 Q→RQ\to RQ→R，证明 P→RP\to RP→R。

    intro hP 假设 P 成立，把目标变为 R。hPQ hP 得到 Q 的证明，再交给 hQR，便得到 R 的证明。这里不是“算出命题真假”，而是把一个证明作为另一个推理的输入。

    关于命题与证明的类型关系，可以继续读 TPIL：Propositions and Proofs。

    2. 交换合取的顺序

    constructor 把目标分成 Q 和 P。已知 h : P ∧ Q，其中 h.1 取出 P 的证明，h.2 取出 Q 的证明。两个 · 分别组织两个子目标，缩进表明各段属于哪个分支。

    练习：先不看答案，写出从 P ∧ Q 推出 P 的证明，再尝试从 P ∧ (Q ∧ R) 推出 R。

    3. 存在性需要给出见证

    对任意自然数 n，存在自然数 m，使得 m=n+nm=n+nm=n+n。

    ⟨n + n, rfl⟩ 同时提供两个部分：选择见证 m := n + n，并证明代入后出现的等式 n + n = n + n。这个例子有意选得很简单，重点是存在量词的证明结构。

    进一步可读 TPIL：Quantifiers and Equality。

    4. 把已有等式用于更大的表达式

    Nat.add_comm a b 是关于自然数加法交换律的已有定理。这里明确给出 a、b，使它表达 a + b = b + a；改写后，目标两边相同。

    遇到一个陌生定理，先输入 #check Nat.add_comm，查看完整类型，再决定该怎样使用。定理名字只是线索，参数和结论才是使用依据。

    五、怎样从小例子走向数学分析

    对于数学专业学习者，我建议采用以下练习顺序。每阶段以“能独立完成小证明”为结束条件，不必追求固定天数。

    阶段 练习重点 完成标志
    认识证明状态 Natural Number Game、本文前两例 能说明每一步的假设和目标如何变化
    逻辑与量词 全称、存在、合取、蕴含和等价 能把一段简单纸笔证明拆成若干小目标
    等式与函数 改写、复合、单射、满射 能查到并正确使用一个已有定理
    集合与数系 集合包含、自然数、整数、实数 能区分定义展开和调用库中结果
    分析入门 数列极限、连续性相关的基础练习 能解释定义中各变量及量词的作用范围

    这份顺序是本文的学习建议。具体章节与练习请跟随 MIL 目录；想较早接触数列极限，也可以选择 Glimpse of Lean 的 SequenceLimits 专题。

    例如纸笔上写：

    ∀ε>0, ∃N∈N, ∀n≥N, ∣un−L∣<ε.\forall\varepsilon>0,\ \exists N\in\mathbb N,\ \forall n\ge N,\ |u_n-L|<\varepsilon. ∀ε>0, ∃N∈N, ∀n≥N, ∣un​−L∣<ε.

    形式化时首先要弄清：ε 的类型是什么，N 可以依赖哪些已引入的量，后面的 n 又是什么类型。掌握这些细节后，再学习 mathlib 已有的极限表示与定理，会更容易理解库接口。

    六、初学时常见的卡点

    拿到了 Lean 3 代码。 老教材中常见 begin ... end 风格，不能直接当成本文的 Lean 4 示例使用。搜索时优先确认教程版本；社区维护的 Lean 4 学习页 可作为入口。

    出现 unknown module prefix 'Mathlib'。 先确认打开的是含 mathlib 依赖的项目根目录，而不只是单独一个文件。教材项目准备完成后再编写示例；不要把模块找不到误认为证明有错。

    exact 报类型不匹配。 对比当前目标与所提供证明的类型。P → Q 是一条推理规则，Q 是它的结论；两者不同。还要留意自然数、整数、实数及其转换。

    rw 没有找到要改写的表达式。 查看等式方向、表达式实际形状和所在位置。反向使用等式时可以写 rw [← h]；若要处理某条假设，需要说明在该假设中改写。

    还留着 sorry。 sorry 允许临时跳过证明，并会带来警告；它适合搭草稿，但不代表该结论已经证明。检查完整证明时需要移除这些占位符。关于证明、公理和计算的边界，见 TPIL：Axioms and Computation。

    不知道库里叫什么。 可以从目标的类型、运算或命名空间出发，在 mathlib API 或官方学习页列出的 Loogle 中查找；找到候选结果后，再核对假设是否满足。
